# 食光点餐：前后端接口实现讲解

这份文档按实际代码梳理前端页面、请求函数和后端处理链。阅读顺序建议：先看“请求如何到达后端”，再找一个具体功能，沿 `页面 → API 函数 → Controller → Service → Mapper → 数据库` 跟踪。

## 1. 前端目录和职责

```text
src/
├─ api/
│  ├─ customer.js       顾客端接口函数
│  └─ admin.js          管理端接口函数和图片上传
├─ router/index.js      URL、页面和登录跳转
├─ stores/token.js      用 Pinia 保存两种身份的 token
├─ utils/request.js     Axios、token 请求头和统一错误处理
├─ utils/display.js     菜品图片、金额和订单状态显示
├─ views/
│  ├─ Login.vue         顾客注册/登录和管理员登录
│  ├─ customer/Customer.vue  点餐、购物车、顾客订单
│  └─ admin/Admin.vue        商家管理页面
├─ App.vue              页面出口 router-view
├─ main.js              注册路由、Pinia 和 Element Plus
└─ style.css            页面样式
```

`big-event` 也是页面调用 `api` 下的函数，接口函数再调用 `utils/request`。这里沿用这个分层。当前管理端的门店、分类、菜品、订单仍共用 `Admin.vue`，根据路由中的 `section` 切换；顾客菜单与订单也共用 `Customer.vue`，并不是每个功能一个组件。

## 2. 请求是怎么到后端的

以查询菜品为例：

1. 用户选择门店或分类，`Customer.vue` 的 `loadDishes()` 读取当前 `store`、`category`。
2. `loadDishes()` 调用 `customerDishListService({ storeId, categoryId })`。
3. `src/api/customer.js` 调用 `request.get('/app/dish/list', { params })`。Axios 把 `params` 放在 URL 查询字符串中。
4. `src/utils/request.js` 的请求拦截器根据 `/app` 或 `/admin` 选对应 token，并放进 `Authorization` 请求头。这里发送的是原始 token，不加 `Bearer`。
5. Axios 的 `baseURL` 是 `/api`；Vite 把 `/api/app/dish/list` 转发给 `http://localhost:8080/app/dish/list`。
6. 后端 `LoginInterceptor` 校验 token；`AppDishController.find()` 接收参数，调用 `AppDishServiceimpl.find()`，再由 `DishMapper` 和 Redis 处理数据。
7. 后端返回 `{ code, message, data }`。响应拦截器在 `code === 0` 时**直接返回 `data`**，所以页面写 `dishes.value = await customerDishListService(...)`，不需要再写 `result.data`。这和 `big-event` 的返回方式不同。

请求体和查询参数的区别：`request.post(url, data)` 的 `data` 是 JSON 请求体；`request.get(url, { params })` 的 `params` 是 URL 查询参数；路径中的 `/{id}` 是路径参数。上传图片使用 `FormData`。

## 3. 顾客端接口

对应前端函数见 `src/api/customer.js`。表中“页面方法”在 `views/Login.vue` 或 `views/customer/Customer.vue`；`Serviceimpl`、`Mapper` 指后端 `ordering-server` 中的类。

| 接口 | 页面方法 → API 函数 | 传入数据 | 后端处理与结果 |
| --- | --- | --- | --- |
| POST `/app/register` | `submit` → `registerService` | JSON：`phone`、`nickname`、`password` | `AppLoginController.register` → `UserServiceimpl.register` → `UserMapper` 查手机号、插入 `t_user`；校验手机号和密码、对密码做哈希，重复手机号拒绝。 |
| POST `/app/login` | `submit` → `customerLoginService` | JSON：`phone`、`password` | `AppLoginController.login` → `UserServiceimpl.login` → `UserMapper` 查用户；密码正确后签发 JWT 并写 Redis，返回 token。前端通过 Pinia 和 localStorage 保存。 |
| GET `/app/store/list` | `loadStores` → `customerStoreListService` | 无 | `AppStoreController.find` → `AppStoreServiceimpl.find` → `StoreMapper`；返回顾客可见的门店列表。 |
| GET `/app/category/list` | `loadStore` → `customerCategoryListService` | 查询参数 `storeId` | `AppCategoryController.list` → `AppCategoryServiceimpl.list` → `CategoryMapper`；查询指定门店的可用分类。 |
| GET `/app/dish/list` | `loadDishes` → `customerDishListService` | 查询参数 `storeId`，可选 `categoryId` | `AppDishController.find` → `AppDishServiceimpl.find` → `DishMapper`；查询门店菜品并使用 Redis 缓存，返回菜品列表。 |
| GET `/app/dish/{id}` | `openDish` → `customerDishDetailService` | 路径 `id` | `AppDishController.getDetail` → `AppDishServiceimpl.getDetail` → `DishMapper`；用于菜品详情弹窗。 |
| GET `/app/cart/list` | `loadCart` → `cartListService` | 可选查询参数 `storeId` | `AppCartController.find` → `CartServiceimpl.find` → `CartMapper`；后端从登录上下文确定用户，返回购物车条目。 |
| POST `/app/cart` | `add` → `cartAddService` | JSON：`dishId`、`quantity` | `AppCartController.add` → `CartServiceimpl.add` → `CartMapper`；检查菜品及数量，新增或累加购物车，然后前端重新查询。 |
| PUT `/app/cart` | `change` → `cartUpdateService` | JSON：`dishId`、`quantity` | `AppCartController.update` → `CartServiceimpl.update` → `CartMapper`；修改当前用户的菜品数量。 |
| DELETE `/app/cart/{id}` | `remove` 或 `change` → `cartDeleteService` | 路径 `id` 是**购物车条目 ID** | `AppCartController.delete` → `CartServiceimpl.delete` → `CartMapper`；数量减到 0 时也走删除接口。 |
| POST `/app/order/submit` | `submit` → `orderSubmitService` | JSON：`storeId`、`pickupType`、可选 `pickupTime` 和 `remark` | `AppOrderController.submit` → `AppOrderServiceimpl.submit`；校验门店和购物车，查询菜品与价格，写入 `t_orders`、`t_order_detail` 并清空本店购物车，使用事务保证一致性。金额由后端计算。 |
| GET `/app/order/list` | `loadOrders` → `customerOrderListService` | 查询参数 `pageNum`、`pageSize`；后端还支持 `status` | `AppOrderController.page` → `AppOrderServiceimpl.page` → `OrderMapper`；只查询当前顾客的订单，返回 `total` 和 `items`。当前页面没有状态筛选控件。 |
| GET `/app/order/{id}` | `openOrder` → `customerOrderDetailService` | 路径订单 `id` | `AppOrderController.getById` → `AppOrderServiceimpl.getById` → `OrderMapper`、`OrderDetailMapper`；限定当前用户并返回订单快照和明细。 |
| PUT `/app/order/cancel/{id}` | `cancel` → `customerOrderCancelService` | 路径订单 `id` | `AppOrderController.cancel` → `AppOrderServiceimpl.cancel` → `OrderMapper`；校验订单属于当前用户且状态允许取消，再更新状态。 |

注意：顾客退出仅清除本地 token；当前后端没有顾客退出接口，所以不能说服务端 Redis 令牌立即失效。

## 4. 管理端接口

对应前端函数见 `src/api/admin.js`。除了管理员登录，页面方法都在 `views/admin/Admin.vue`。`refresh()` 根据 `section` 加载数据，`save()` 根据当前功能选择新增或修改函数。

| 接口 | 页面方法 → API 函数 | 传入数据 | 后端处理与结果 |
| --- | --- | --- | --- |
| POST `/admin/login` | `Login.vue` 的 `submit` → `adminLoginService` | JSON：`username`、`password` | `AdminController.login` → `AdminServiceimpl.login` → `EmployeeMapper`；验证员工并签发 token、写入 Redis。 |
| GET `/admin/info` | `init` → `adminInfoService` | 无 | `AdminController.info` 根据登录上下文查询员工信息；页面用返回的 `role` 和 `storeId` 判断展示。 |
| POST `/admin/logout` | `logout` → `adminLogoutService` | 请求头中的 token | `AdminController.logout` 删除 Redis 中的 token；前端再清除本地管理员 token。 |
| GET `/admin/store/page` | `refresh` / `loadStores` → `storePageService` | `pageNum`、`pageSize`，可选 `name`、`status` | `StoreController.page` → `StoreServiceimpl.page` → `StoreMapper`；PageHelper 分页并按管理员权限限制门店范围。 |
| POST `/admin/store` | `save` → `storeAddService` | JSON 门店信息 | `StoreController.addStore` → `StoreServiceimpl.add` → `StoreMapper`；后端要求超级管理员。 |
| PUT `/admin/store` | `save` → `storeUpdateService` | JSON：`id`、`name` 等 | `StoreController.updateStore` → `StoreServiceimpl.updateStore` → `StoreMapper`；后端校验可修改的门店。 |
| DELETE `/admin/store` | `remove` → `storeDeleteService` | 查询参数 `id` | `StoreController.delete` → `StoreServiceimpl.delete`；仅超管可删除，事务中清理门店关联数据。页面操作前会二次确认。 |
| GET `/admin/category/list` | `refresh` / `loadCategories` → `categoryListService` | 超管查询时传 `storeId` | `CategoryController.getCategory` → `CategoryServiceimpl.getCategory` → `CategoryMapper`；普通门店管理员由登录信息确定门店。 |
| POST `/admin/category` | `save` → `categoryAddService` | JSON：`name`、`sort`、`status` | `CategoryController.addCategory` → `CategoryServiceimpl.add` → `CategoryMapper`；门店归属由后端登录上下文确定。 |
| PUT `/admin/category` | `save` → `categoryUpdateService` | JSON：`id`、`name` 等 | `CategoryController.updateCategory` → `CategoryServiceimpl.updateCategory` → `CategoryMapper`；检查分类归属后更新。 |
| DELETE `/admin/category` | `remove` → `categoryDeleteService` | 查询参数 `id` | `CategoryController.deleteCategory` → `CategoryServiceimpl.deleteCategory` → `CategoryMapper`；存在关联菜品时后端拒绝删除。 |
| GET `/admin/dish/page` | `refresh` → `dishPageService` | `pageNum`、`pageSize`，可选 `name`、`status`、`categoryId` | `DishController.page` → `DishServiceimpl.page` → `DishMapper`；先按当前门店过滤，再通过 PageHelper 分页。 |
| POST `/admin/dish` | `save` → `dishAddService` | JSON：`categoryId`、`name`、`price` 等 | `DishController.addDish` → `DishServiceimpl.addDish` → `DishMapper`；验证分类和所属门店后插入。 |
| PUT `/admin/dish` | `save` → `dishUpdateService` | JSON：`id`、`categoryId`、`name`、`price` 等 | `DishController.updateDish` → `DishServiceimpl.updateDish` → `DishMapper`；校验后修改并处理相关缓存。 |
| PUT `/admin/dish/status/{id}` | `toggleDish` → `dishStatusService` | 路径菜品 `id`，查询参数 `status` | `DishController.updateDishStatus` → `DishServiceimpl.updateDishStatus` → `DishMapper`；状态 1 上架、0 下架。 |
| DELETE `/admin/dish` | `remove` → `dishDeleteService` | 查询参数 `id` | `DishController.deleteDish` → `DishServiceimpl.deleteDish` → `DishMapper`；后端检查门店归属并删除。 |
| GET `/admin/order/page` | `refresh` → `adminOrderPageService` | `pageNum`、`pageSize`，可选 `status`、`beginTime`、`endTime` | `OrderController.page` → `OrderServiceimpl.page` → `OrderMapper`；按当前门店、状态和时间分页。 |
| PUT `/admin/order/accept/{id}` | `orderAction` → `adminOrderAcceptService` | 路径订单 `id` | `OrderController.accept` → `OrderServiceimpl.accept` → `OrderMapper`；待接单变为已接单。 |
| PUT `/admin/order/complete/{id}` | `orderAction` → `adminOrderCompleteService` | 路径订单 `id` | `OrderController.complete` → `OrderServiceimpl.complete` → `OrderMapper`；已接单变为已完成。 |
| PUT `/admin/order/cancel/{id}` | `orderAction` → `adminOrderCancelService` | 路径 `id`，JSON：`cancelReason` | `OrderController.cancel` → `OrderServiceimpl.cancel` → `OrderMapper`；输入原因后拒单，后端检查状态和门店。 |
| GET `/admin/stats/today` | `refresh` → `todayStatsService` | 无 | `StatsController.getStats` → `StatsServiceimpl.getStats` → `OrderMapper`；统计当前门店今日订单、状态数量和营业额。 |
| POST `/admin/upload` | `upload` → `uploadService` | `FormData` 中的 `file` | `FileUploadController.upload` → `FileUploadUtil.uploadImage`；校验并保存图片，返回 URL，前端将 URL 放入菜品表单。该接口不是 Controller → Service → Mapper 链。 |

## 5. 两个关键流程

### 加入购物车

```text
点击“加入购物车”
→ Customer.vue 的 add(dish)
→ cartAddService({ dishId, quantity: 1 })
→ POST /app/cart
→ AppCartController.add
→ CartServiceimpl.add
→ CartMapper → t_cart
→ loadCart() 重新查询，页面显示最新数量和金额
```

`dishId` 是菜品 ID；购物车删除接口使用的 `id` 是购物车条目 ID，两者不能混淆。`userId` 不由前端传入，而是后端从 token 确定。

### 提交订单

```text
确认取餐方式、时间、备注
→ Customer.vue 的 submit()
→ orderSubmitService(body)
→ POST /app/order/submit
→ AppOrderController.submit
→ AppOrderServiceimpl.submit
→ StoreMapper / CartMapper / DishMapper 检查门店、购物车和菜品
→ OrderMapper 写订单 → OrderDetailMapper 写明细 → 清理购物车
→ 返回订单号 → 前端刷新购物车并跳转“我的订单”
```

事务的作用：任何一步失败时，数据库回滚同一事务中的订单、明细和购物车更改。订单金额使用后端查询到的价格计算，不能信任浏览器传入的金额。

## 7. 当前边界

本次整理侧重结构和可读性，不代表每个接口都已在当前数据库完成端到端测试。超级管理员和门店管理员的实际可操作范围以服务端权限检查为准；删除门店会清理关联数据。历史数据库若未给相关表的 `id` 配置 `AUTO_INCREMENT`，新增操作仍可能失败，不能直接重建数据库解决。
