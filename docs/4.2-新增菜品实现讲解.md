# 4.2 新增菜品实现讲解

当前按接口文档实现 `POST /admin/dish`。图片上传留到 11.1，新增菜品时允许省略 `image`，数据库保存为 `null`。

## 1. 先用一个请求理解完整过程

在 Postman 或 Apifox 中发送：

```http
POST /admin/dish
Authorization: 登录获得的原始token
Content-Type: application/json
```

```json
{
  "name": "水煮牛肉",
  "categoryId": 1,
  "price": 48.00,
  "description": "麻辣鲜香"
}
```

示例中的分类 ID `1` 要替换成当前门店实际存在的分类，可先调用 3.1 分类列表接口查看。

假设登录员工的 JWT 中 `storeId=2`，后端最终保存的菜品归属就是门店 2。前端只需选择门店 2 的分类，不需要传 `storeId`。

成功响应与接口文档一致：

```json
{"code":0,"message":"操作成功","data":null}
```

## 2. Controller：把 JSON 变成 Dish

入口在 `DishController.addDish()`：

```java
public Result addDish(@Validated(Dish.Add.class) @RequestBody Dish dish)
```

- `@RequestBody`：把请求体里的 JSON 转换成 `Dish` 对象。
- `@Validated(Dish.Add.class)`：启用实体的新增校验组。新增不要求主键，名称、分类、价格的必填约束会生效。
- Controller 调用 Service，业务成功后用 `Result.success()` 返回统一结果。

## 3. Service：判断能不能新增，并补全服务端字段

`DishServiceimpl.addDish()` 依次执行：

1. 调用 `AdminContextUtil.getCurrentAdminStoreId()`，检查登录身份、管理员角色和门店绑定。
2. 检查名称不是空白、分类 ID 有效、价格非负、状态为 0 或 1，并检查数据库字段容量。
3. 不传 `status` 时默认上架（1），不传 `sort` 时默认 0。
4. 锁定并检查当前门店，再查询并锁定“分类 ID + 当前门店 ID”匹配的分类。
5. 清空前端传入的主键，覆盖门店 ID，去除名称首尾空格，生成创建、更新时间。
6. 调用 Mapper 插入；影响行数不是 1 时抛出业务异常。

字段来源如下：

| 字段 | 来源或处理方式 |
| --- | --- |
| name、categoryId、price、description | 前端传入，服务端校验 |
| image | 可不传；空字符串或纯空格也转为 null |
| status | 前端可传 0 或 1，不传默认 1 |
| sort | 前端可传，不传默认 0 |
| storeId | 服务端从当前登录信息获取并覆盖 |
| createTime、updateTime | 服务端生成，新增时使用同一个时间 |
| id | 数据库自增，前端传入的值不用于插入 |

### 为什么不能比较前端的 dish.storeId？

你原来的代码是：

```java
long storeId = AdminContextUtil.getCurrentAdminStoreId();
if (dish.getStoreId() != storeId) {
    throw new BizException("不属于该门店");
}
```

文档要求前端不用传门店 ID，所以 `dish.getStoreId()` 通常为 `null`。Java 为了和 `long` 比较会自动拆箱，这时会抛出空指针异常。

新增记录的门店归属由后台决定，正确处理是 `dish.setStoreId(storeId)`。需要校验归属的是前端选中的已有分类：分类必须存在，而且属于当前门店。

### 为什么需要事务和行锁？

事务覆盖“检查门店、检查分类、插入菜品”。方法加上 `@Transactional`，发生运行时异常时回滚数据库操作。

这里复用了 `StoreMapper.findByIdForUpdate()` 和 `CategoryMapper.findByIdAndStoreIdForUpdate()`，统一先锁门店、再锁分类。分类删除和整店删除也遵循相同顺序，使本项目的这些写操作互相等待，避免检查完分类后分类又被删除。

价格字段对应数据库 `DECIMAL(10,2)`：最多 8 位整数和 2 位有效小数。`48.000` 可以精确表示为 `48.00`；`48.001` 会被拒绝，避免数据库静默舍入。

## 4. Mapper：把对象字段写入数据库

Mapper 沿用注解加字符串拼接的风格：

```java
@Insert("insert into t_dish(store_id, category_id, name, price, image, description, status, sort, create_time, update_time) " +
        "values(#{storeId}, #{categoryId}, #{name}, #{price}, #{image}, #{description}, #{status}, #{sort}, #{createTime}, #{updateTime})")
@Options(useGeneratedKeys = true, keyProperty = "id")
int addDish(Dish dish);
```

- 插入字段不包括自增主键 `id`。
- `#{storeId}` 读取传入对象的 `dish.storeId`，其余占位符同理。
- 方法只有一个实体参数，可以直接使用属性名，不需要逐个写 `@Param`。
- 返回的 `int` 是影响行数，成功插入一条通常返回 1。
- `@Options` 将数据库生成的主键回填到 `dish.id`；影响行数和主键是两个不同的值。

完整链路是：Controller 接收 JSON → Service 校验、补全字段 → Mapper 执行 INSERT → 数据库存储 → Controller 返回统一成功响应。
