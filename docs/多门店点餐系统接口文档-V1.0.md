# 0. 通用说明

## 0.1 响应格式

所有接口（除文件上传的特殊说明外）统一返回以下 JSON 结构：

| 名称 | 类型 | 是否必须 | 默认值 | 备注 |
| --- | --- | --- | --- | --- |
| code | number | 必须 | 无 | 响应码，0-成功，1-失败 |
| message | string | 非必须 | 无 | 提示信息 |
| data | object | 非必须 | 无 | 返回的数据，可能是对象、数组或字符串 |

**成功响应样例**

```json
{"code":0,"message":"操作成功","data":null}
```

**失败响应样例**

```json
{"code":1,"message":"用户名已被占用","data":null}
```

> **开发约定**：`Result` 类中的字段名为 `message`（与后端 `pojo/Result.java` 保持一致），不是 `msg`。

## 0.2 登录与令牌

1. 管理端登录成功后，系统下发 JWT 令牌（token）。
2. 后续每次请求，都需要在**请求头 header** 中携带该令牌：

| 请求头名称 | 值 | 说明 |
| --- | --- | --- |
| Authorization | 登录时下发的 JWT 令牌 | 不需要加 Bearer 前缀，直接放原始 token |

3. 令牌同时保存于 Redis，服务端会二次校验，因此可以主动失效（如修改密码后强制下线）。
4. **如果检测到用户未登录或令牌失效，则 http 响应状态码为 401**，响应体为空。
5. 令牌有效期为 12 小时。
6. 无需携带令牌的接口（白名单）：`/admin/login`、`/app/login`、`/app/register`、`/admin/upload`。

## 0.3 分页格式

所有分页接口的响应 `data` 结构统一如下：

| 名称 | 类型 | 是否必须 | 默认值 | 备注 |
| --- | --- | --- | --- | --- |
| total | number | 必须 | 无 | 总记录数 |
| items | array | 必须 | 无 | 当前页数据列表 |

```json
{"code":0,"message":"操作成功","data":{"total":8,"items":[]}}
```

> 分页由 PageHelper 实现，请求参数统一为 `pageNum`（当前页码）与 `pageSize`（每页条数）。

## 0.4 状态码与枚举

**订单状态（status）**

| 值 | 含义 | 可流转到 |
| --- | --- | --- |
| 1 | 待接单 | 2 已接单 / 4 已取消 |
| 2 | 已接单 | 3 已完成 |
| 3 | 已完成 | 终态，不可再变更 |
| 4 | 已取消 | 终态，不可再变更 |

**其他枚举**

| 字段 | 值 | 含义 |
| --- | --- | --- |
| payStatus | 0 / 1 | 未支付 / 已支付（模拟支付） |
| pickupType | 1 / 2 | 到店自取 / 堂食扫码 |
| role（员工） | 1 / 2 | 超级管理员（可管所有门店）/ 门店管理员（只看本店） |
| status（门店） | 1 / 0 | 营业中 / 已打烊 |
| status（分类） | 1 / 0 | 启用 / 禁用 |
| status（菜品） | 1 / 0 | 上架 / 下架 |
| status（员工） | 1 / 0 | 启用 / 禁用 |

> **门店数据隔离**：管理端所有涉及门店数据的接口，服务端都会从 JWT 中取出当前员工的 `storeId` 并强制过滤，前端**不需要也不应该**传该字段（超级管理员除外）。

# 1. 管理端 - 登录相关接口

## 1.1 管理员登录

### 1.1.1 基本信息

请求路径：/admin/login

请求方式：POST

接口描述：该接口用于管理员（员工）登录后台系统

### 1.1.2 请求参数

请求参数格式：application/json

请求参数说明：

| 参数名称 | 类型 | 是否必须 | 备注 |
| --- | --- | --- | --- |
| username | string | 是 | 用户名，3~20 位非空字符 |
| password | string | 是 | 密码，5~16 位非空字符 |

请求数据样例：

```json
{"username":"admin","password":"123456"}
```

### 1.1.3 响应数据

响应数据类型：application/json

响应参数说明：

| 名称 | 类型 | 是否必须 | 默认值 | 备注 |
| --- | --- | --- | --- | --- |
| code | number | 必须 | 无 | 响应码，0-成功，1-失败 |
| message | string | 非必须 | 无 | 提示信息 |
| data | string | 非必须 | 无 | 返回的数据，登录成功时为 JWT 令牌 |

响应数据样例：

```json
{"code":0,"message":"操作成功","data":"eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJjbGFpbXMiOnsiaWQiOjEsInVzZXJuYW1lIjoiYWRtaW4ifSwiZXhwIjoxNzkxNzU4MDAwfQ.xxxxx"}
```

失败样例：

```json
{"code":1,"message":"密码错误","data":null}
```

### 1.1.4 备注

登录成功后，令牌需要保存到浏览器本地（localStorage），并在后续请求的请求头 `Authorization` 中携带。

## 11.1 图片上传

### 11.1.1 基本信息

请求路径：/admin/upload

请求方式：POST

接口描述：该接口用于上传图片（单文件），返回可直接访问的图片地址

### 11.1.2 请求参数

请求参数格式：multipart/form-data

请求参数说明：

| 参数名称 | 类型 | 是否必须 | 备注 |
| --- | --- | --- | --- |
| file | file | 是 | 图片文件，支持 jpg / png / gif |

请求数据样例：

```
Content-Type: multipart/form-data; boundary=----WebKitFormBoundary7MA4YWxkTrZu0gW
```

### 11.1.3 响应数据

响应数据类型：application/json

响应参数说明：

| 名称 | 类型 | 是否必须 | 默认值 | 备注 |
| --- | --- | --- | --- | --- |
| code | number | 必须 | 无 | 响应码，0-成功，1-失败 |
| message | string | 非必须 | 无 | 提示信息 |
| data | string | 必须 | 无 | 图片访问地址（相对路径） |

响应数据样例：

```json
{"code":0,"message":"操作成功","data":"/upload/9f8e7d6c5b4a4e3f8d2c1b0a9e8f7d6c.jpg"}
```

### 11.1.4 备注

1. 需在设置好购物车等业务前先上传图片，把返回的地址填入菜品的 `image` 字段。
2. 文件按 UUID 重命名后存放在服务器本地目录（配置项 `ordering.upload.dir`），通过静态资源映射对外暴露，访问前缀为 `/upload/`。
3. 完整访问地址 = 服务端域名 + 返回的 `data`，例如 `http://localhost:8080/upload/9f8e...jpg`。
4. 该接口在 JWT 白名单内（上传图片时不校验 token），若需要鉴权可将其从白名单移除。
