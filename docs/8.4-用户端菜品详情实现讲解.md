# 8.4 用户端菜品详情实现讲解

这次接口是 `GET /app/dish/{id}`，根据一道菜的 ID 返回一个对象。它可以理解为：8.3 是打开一家店的菜单，8.4 是点开菜单里的某一道菜。

## 你原来已经写对的部分与本次修改

你这次已经主动加上 `@GetMapping("/{id}")`，并且继续保持 Controller → Service → Mapper 的调用链，Service 中也检查了输入 ID。相比 8.3 初写时遗漏请求映射，这一点已经改善。

主要问题是把列表接口的参数和返回类型带到了详情接口：

| 原实现 | 修改后 | 原因 |
| --- | --- | --- |
| 路径有 `{id}`，却用 `@RequestParam("storeId")` 接收 | `@PathVariable("id") Long id` | 文档传的是路径中的菜品 ID |
| `List<Dish>` | `AppDishVO` | 详情返回一道菜，而不是整店列表 |
| 调用 `dishMapper.list(null, 1, null, storeId)` | 调用 `dishMapper.findById(id)` | 按菜品主键查询单条记录 |
| 上架状态固定传 1 | 详情保留原状态 | 文档明确说明详情状态可以是 1 上架或 0 下架 |
| 缺少未找到菜品的判断 | 抛出 `BizException("菜品不存在")` | 对齐失败响应 |

方法名统一为 `getDetail`，沿用 Java 常见的驼峰命名方式。

## Controller：从哪里拿参数

```java
@GetMapping("/{id}")
public Result<AppDishVO> getDetail(@PathVariable("id") Long id) {
    AppDishVO dish = appDishService.getDetail(id);
    return Result.success(dish);
}
```

请求 `/app/dish/101` 时，`id` 就是 `101`。

这与 8.3 的参数来源不同：

```text
/app/dish/list?storeId=1 → @RequestParam("storeId")
/app/dish/101           → @PathVariable("id")
```

8.4 不要求传门店 ID。菜品 ID 是数据库主键，可以唯一找到菜品；顾客也没有员工绑定门店的限制。

## Service：校验、查找、判断、转换

```java
public AppDishVO getDetail(Long id) {
    if (id == null || id < 1) {
        throw new BizException("请选择有效的菜品ID");
    }
    Dish dish = dishMapper.findById(id);
    if (dish == null) {
        throw new BizException("菜品不存在");
    }
    return AppDishVO.from(dish);
}
```

顺序是：先拒绝空值、0、负数，再查数据库；没有对应记录时给出文档要求的错误；查到后使用已有 `AppDishVO.from` 创建返回对象。

Service 接口和实现类同步改为 `AppDishVO getDetail(Long id)`。`AppDishVO` 复用 8.3 的九个字段，也符合 8.4 示例中的返回结构，不暴露创建和更新时间。

## Mapper：按 ID 查询一行

```java
@Select("select * from t_dish where id = #{id}")
Dish findById(@Param("id") Long id);
```

`#{id}` 是 MyBatis 绑定参数。找到记录时映射为一个 `Dish`，找不到时返回 `null`。这是普通查询，不需要 `FOR UPDATE`。

这里不添加 `status = 1`：8.4 文档允许返回下架状态，与 8.3 只列出上架菜品不同。详情没有文档规定的缓存策略，本次直接查库，后续请求能读到数据库当前的价格与上下架状态。

## 成功和失败怎样返回

```text
用户携带 token 请求 /app/dish/101
→ 登录拦截器验证顾客身份
→ Controller 取出路径中的 101
→ Service 校验 ID
→ Mapper 查询 t_dish
→ Dish 转 AppDishVO
→ Controller 返回 Result.success(dish)
```

返回的 `data` 是对象：

```json
{"code":0,"message":"操作成功","data":{"id":101,"storeId":1,"categoryId":11,"name":"宫保鸡丁","price":38.00,"image":"/upload/chicken.jpg","description":"微辣","status":1,"sort":2}}
```

如果不存在，由 Service 抛出的异常交给已有全局异常处理器，得到：

```json
{"code":1,"message":"菜品不存在","data":null}
```

缺失或无效 token 继续由拦截器返回 HTTP 401；路径 ID 无法转换为 Long 时使用已有参数类型错误处理。
